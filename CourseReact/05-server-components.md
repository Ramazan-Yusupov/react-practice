# React · 05 · Server Components и Server Functions

> Это концептуальный файл: в вашем проекте (Vite SPA) серверных компонентов нет. Он нужен, чтобы осознанно перейти на **TanStack Start**, где механика серверных функций своя.

## Идея
- **Server Components (RSC)** рендерятся на сервере, их код и зависимости не попадают в бандл клиента; могут напрямую читать БД/файлы и быть `async`.
- **Client Components** (`'use client'`) — интерактивность: состояние, эффекты, обработчики.
- **Server Functions / Actions** (`'use server'`) — функции, которые клиент вызывает как обычные, а выполняются они на сервере.

```tsx
// Server Component
export async function Tasks() {
  const tasks = await db.tasks.findMany();
  return <ul>{tasks.map((t) => <li key={t.id}>{t.title}</li>)}</ul>;
}
```
Границы: серверный компонент может импортировать клиентский, обратное — нет (клиентский получает серверный только как `children`/prop). Пропсы через границу должны быть **сериализуемы** (без функций и классов).

## Что RSC решают и чего не решают
Решают: меньше JS на клиенте, ближе данные к серверу, нет «водопадов» запросов из клиента. Не решают: интерактивность, кэш на клиенте, оптимистичные обновления — для них остаются Client Components и TanStack Query.

## Как это связано с TanStack Start
Start строится на собственных серверных функциях (`createServerFn`) и интеграции с Router/Query, а не на «магии директив». Поддержка RSC в Start развивается — актуальный статус смотрите в документации библиотеки. Практический вывод: сейчас вы переносите свой Express-код в **серверные функции Start**, а компонентную модель RSC изучаете как фундамент.
