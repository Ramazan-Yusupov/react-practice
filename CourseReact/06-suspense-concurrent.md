# React · 06 · Suspense и конкурентный рендер

## Suspense
`<Suspense fallback={...}>` показывает запасной UI, пока вложенные компоненты «ждут» (`lazy`, `use(promise)`, `useSuspenseQuery`).
```tsx
const Practice = lazy(() => import('./Practice/Practice'));
<Suspense fallback={<LoadingUI />}>
  <Routes>...</Routes>
</Suspense>
```
Размещайте границы **осмысленно**: одна на всё приложение = мигает всё; по одной на блок = локальные скелетоны.

## Error Boundaries
Ловят ошибки рендера потомков. Своего хука для них в React нет: пишут классом или берут `react-error-boundary`. Связка по умолчанию: `ErrorBoundary` снаружи, `Suspense` внутри. Ошибки в обработчиках событий и асинхронном коде границы **не ловят**.

## Transitions
- **`startTransition` / `useTransition`** — помечают обновление несрочным: старый UI остаётся интерактивным, пока готовится новый. При подвисании Suspense внутри transition React **не заменяет** уже показанный контент на fallback.
- **`useDeferredValue`** — «отстающее» значение для тяжёлых производных (фильтр списка по вводу).
```tsx
const deferred = useDeferredValue(query);
const isStale = query !== deferred;
<List filter={deferred} className={isStale ? 'opacity-60' : ''} />
```

## Конкурентный рендер в двух фразах
React может **прервать** рендер, начатый для несрочного обновления, обработать срочное (ввод) и вернуться. Поэтому рендер обязан быть чистым: он может вызываться несколько раз.
