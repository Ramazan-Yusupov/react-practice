# React · 04 · React Compiler

## Что делает
Компилятор на этапе сборки автоматически мемоизирует компоненты и хуки (аналог `useMemo`/`useCallback`/`memo`), анализируя потоки данных. Вы пишете «простой» код, а лишние перерендеры убирает компилятор. Версия 1.0 стабильна с октября 2025.

## Требования к коду
Компилятор безопасен только для кода по **правилам React**:
- компоненты и хуки чистые;
- props/state/контекст не мутируются;
- `ref.current` не читается/не пишется в рендере;
- побочные эффекты — в эффектах и обработчиках.
Нарушающий код компилятор **пропускает** (оставляя как есть) либо выдаёт предупреждение линтера.

## Подключение (Vite)
Ваш `README` пишет, что компилятор выключен из-за влияния на dev/build. Подключение в духе официального гайда (react.dev → Learn → React Compiler → Installation, сверьте под вашу версию `@vitejs/plugin-react`):
```bash
npm i -D babel-plugin-react-compiler
```
```ts
// vite.config.ts (вариант для plugin-react с Babel)
react({ babel: { plugins: [['babel-plugin-react-compiler', {}]] } }),
```
Режимы: по умолчанию компилируется всё; `compilationMode: 'annotation'` — только функции с директивой `'use memo'`. Исключить компонент: `'use no memo'` в начале функции.

## Как увидеть результат
В React DevTools у скомпилированных компонентов бейдж **«Memo ✨»**. Профилирование: вкладка Profiler → «Why did this render?» либо дорожки Performance (файл 03).

## Что делать с `useMemo` и `useCallback`
Новый код пишем без них, пока профилировщик не показал проблему. Существующие не удаляйте массово: они иногда нужны как **стабильные зависимости эффектов**. Удаляйте, когда уверены.

## ESLint
`eslint-plugin-react-hooks` (v6+) содержит правила, питающиеся логикой компилятора (`purity`, `set-state-in-effect`, `refs`, `immutability` и др.). У вас часть выключена в `eslint.config.js`: это «долг», который компилятор тоже заметит.

## Проверь себя
1. Что произойдёт с компонентом, мутирующим props?
2. Когда `useCallback` всё ещё имеет смысл?
3. Чем режим `annotation` удобен при постепенном внедрении?

## Задания в проекте
1. Сделайте замер до компилятора: список из 2 000 карточек с нестабильными колбэками, отметьте число рендеров в Profiler.
2. Подключите компилятор, повторите замер, найдите бейдж «Memo ✨» в DevTools.
3. Включите в ESLint `react-hooks/purity` и `set-state-in-effect`, исправьте предупреждения, посмотрите, перестали ли компоненты пропускаться.
4. Намеренно сломайте правило (мутация props) и посмотрите, как компилятор и линтер реагируют.
5. Сравните размер и время сборки (`npm run build`) с компилятором и без — зафиксируйте в заметках.
