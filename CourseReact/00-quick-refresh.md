# React · 00 · Быстрое повторение

Опыт у вас есть, поэтому только то, на чём ломаются даже опытные: модель рендера. Всё дальнейшее (хуки, Actions, Compiler) опирается на неё.

## 1. Рендер ≠ обновление DOM
Три фазы: **триггер** (первый `createRoot().render` или смена состояния) → **рендер** (React вызывает ваши функции-компоненты, получает JSX) → **коммит** (React вносит минимальные изменения в DOM, затем запускает эффекты).
Компонент во время рендера должен быть **чистой функцией**: те же props/state/context → тот же JSX. Никаких мутаций внешних переменных, `Math.random()`/`Date.now()` в теле, запросов.

## 2. Состояние — это снимок
```tsx
function Counter() {
  const [n, setN] = useState(0);
  function handle() {
    setN(n + 1); // n в этом рендере всегда 0
    setN(n + 1); // оба вызова ставят 1
    setN((prev) => prev + 1); // updater: берёт актуальное, итого 2 после предыдущих
  }
  return <button onClick={handle}>{n}</button>;
}
```
`setState` не меняет переменную `n` в текущем рендере, а планирует **новый** рендер с новым снимком. Объекты и массивы в состоянии не мутируем, а копируем: `setItems(items.map(...))`.

## 3. Пакетная обработка (batching)
Все `setState` в одном обработчике (и в промисах, таймерах с React 18) объединяются в один ререндер. `flushSync` нужен только когда DOM нужно прочитать сразу после обновления.

## 4. Ключи
`key` определяет **идентичность** элемента между рендерами. Индекс массива как ключ ломает состояние при вставке/удалении/сортировке. Смена `key` у компонента **сбрасывает его состояние** — это легальный способ «перезагрузить» форму: `<Form key={userId} />`.

## 5. Эффекты — синхронизация с внешним миром
Эффект описывает, как **синхронизироваться** с внешней системой (сокет, таймер, подписка, не-React виджет), а не «что сделать после рендера».
```tsx
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id); // cleanup — обязателен для подписок
}, [tick]);
```
Не нужен эффект: для вычисляемых значений (считайте в рендере), для реакции на клик (обработчик), для запросов данных в «рабочем» коде (для этого есть TanStack Query).

## 6. StrictMode
В dev React монтирует компонент, размонтирует и монтирует снова, чтобы вскрыть эффекты без cleanup и нечистые рендеры. Ваш `main.tsx` уже обёрнут в `<StrictMode>`: двойной `console.log` в `useCards` («📡 Fetching cards») — это он и есть.

## 7. Поднятие состояния и controlled-компоненты
Состояние живёт в ближайшем общем родителе. Controlled input: `value` + `onChange`. Uncontrolled: значение читается из DOM (`FormData`) — в React 19 это основной путь для форм с Actions (см. файл 02).
