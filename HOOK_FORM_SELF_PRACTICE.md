# React Hook Form — самостоятельная практика

Этот файл — рабочая тетрадь для курса в проекте **React + TypeScript + Tailwind**. Здесь нет готовых решений: цель — написать формы самостоятельно, а затем сравнить свою реализацию с интерактивными примерами в `src/pages/HookForm/HookForm.tsx`.

> **Правило:** сначала сделай задание, затем открывай соответствующий demo-компонент для сверки. Не копируй его до первой попытки.

---

## Как работать

1. Запусти проект:

   ```bash
   npm run dev
   ```

2. Создай свой рабочий файл, например:

   ```text
   src/pages/HookForm/MyHookFormPractice.tsx
   ```

3. Собирай задания последовательно. После каждого шага запускай проверки:

   ```bash
   npm run lint
   npm run build
   ```

4. Для интерфейса переиспользуй готовые компоненты проекта:

   ```ts
   import { Button, Card, Form, Input } from '@/shared/ui';
   ```

5. Для сверки используй уже готовые компоненты в файле:

   ```text
   src/pages/HookForm/HookForm.tsx
   ```

---

## Что ты построишь

К финалу у тебя будет мини-приложение **«Регистрация команды на проект»**:

- данные аккаунта;
- валидация email, пароля и числовых полей;
- зависимое отображение UI через `useWatch`;
- кастомный выбор тарифа через `Controller`;
- динамический список участников через `useFieldArray`;
- декомпозиция формы через `FormProvider`;
- асинхронная отправка, загрузка и серверная ошибка.

## Шаг 1. `useForm`, типы и `register`

**Цель:** связать нативные поля с React Hook Form и получить строго типизированные данные при отправке.

### Данные формы

Опиши тип `ProfileValues`:

| Поле | Тип | Начальное значение |
|---|---|---|
| `name` | `string` | пустая строка |
| `email` | `string` | пустая строка |
| `role` | union: `frontend \| backend \| design` | `frontend` |

### Сделай

- [ ] Вызови `useForm<ProfileValues>()` с `defaultValues`.
- [ ] Подключи два поля `Input`: имя и email.
- [ ] Добавь нативный `select` для роли.
- [ ] Свяжи все поля через `register`.
- [ ] Передай обработчик в `handleSubmit`.
- [ ] На submit выведи объект данных в `console.log` или в JSON-панель рядом с формой.
- [ ] Добавь кнопку «Очистить», которая вызывает `reset()`.

### Проверь себя

- [ ] При submit в результат попадают ровно `name`, `email` и `role`.
- [ ] После `reset()` возвращается выбранная роль `frontend`.
- [ ] TypeScript не позволяет зарегистрировать несуществующее поле, например `register('username')`.

<details>
<summary>Подсказка</summary>

`register` возвращает props для поля. Их нужно развернуть непосредственно в компонент input/select: `...register('имяПоля')`.

</details>

**Сверка после выполнения:** `RegisterDemo` в `src/pages/HookForm/HookForm.tsx`.

## Шаг 2. Валидация и `formState.errors`

**Цель:** дать пользователю понятную обратную связь до отправки формы.

### Данные формы

Создай `RegistrationValues`:

| Поле | Тип | Правила |
|---|---|---|
| `email` | `string` | обязательное, валидный email |
| `password` | `string` | обязательное, минимум 8 символов |
| `confirmPassword` | `string` | совпадает с `password` |
| `age` | `number` | от 18 до 120 |

### Сделай

- [ ] Настрой `mode: 'onChange'` в `useForm`.
- [ ] Добавь `required`, `pattern` и `minLength` с русскими сообщениями.
- [ ] Для `age` используй `valueAsNumber: true`.
- [ ] Используй `validate`, чтобы сверить пароль и его повтор.
- [ ] Получи `errors` и `isValid` из `formState`.
- [ ] Передай текст ошибки в готовый проп `error` компонента `Input`.
- [ ] Заблокируй кнопку отправки или покажи статус, когда форма невалидна.

### Проверь себя

- [ ] При неверном email появляется сообщение, а submit не проходит.
- [ ] Число в `age` приходит в обработчик как `number`, а не строка.
- [ ] При изменении пароля поле подтверждения снова корректно проверяется.
- [ ] При валидной форме `isValid` становится `true`.

<details>
<summary>Подсказка: как получить пароль без отдельного состояния</summary>

Используй `useWatch({ control, name: 'password' })` или `watch('password')`. Для интерфейса, который подписывается на отдельное поле, предпочтительнее `useWatch`.

</details>

**Сверка после выполнения:** `ValidationDemo`.

## Шаг 3. Программное управление значениями

**Цель:** освоить `useWatch`, `setValue`, `trigger`, `getValues`, `reset` и состояние формы.

### Сценарий

Создай форму задачи со значениями:

```ts
type TaskValues = {
  title: string;
  note: string;
  newsletter: boolean;
};
```

### Сделай

- [ ] Добавь обязательный `title` с минимум 3 символами.
- [ ] Через `useWatch` выведи live JSON всех данных формы.
- [ ] Создай кнопку «Заполнить демо».
- [ ] В обработчике кнопки заполни `title` и `note` через `setValue`.
- [ ] При заполнении программно отметь поле как changed/touched и сразу запусти валидацию.
- [ ] Добавь кнопку «Проверить», которая вызывает `trigger()`.
- [ ] Покажи `isDirty`, `isValid`, `dirtyFields`, `touchedFields` и значение `getValues('title')`.
- [ ] Добавь кнопку сброса.

### Проверь себя

- [ ] `isDirty` становится `true` после ручного ввода и после «Заполнить демо».
- [ ] После `reset()` флаги меняются на исходное состояние.
- [ ] `trigger()` возвращает результат проверки и показывает ошибки, даже если пользователь не отправлял форму.

<details>
<summary>Подсказка</summary>

У `setValue` есть третий аргумент с флагами `shouldDirty`, `shouldTouch` и `shouldValidate`.

</details>

## Шаг 4. `Controller` для кастомного UI

**Цель:** подключить компоненты, которые не являются обычным input с доступным `ref`.

### Данные формы

```ts
type Priority = 'low' | 'medium' | 'high';

type TaskSettingsValues = {
  priority: Priority;
  estimate: number;
  terms: boolean;
};
```

### Сделай

- [ ] Создай три кнопки выбора приоритета: Low, Medium, High.
- [ ] Управляй ими с помощью `Controller`, а не `register`.
- [ ] Добавь range от 1 до 16 часов через `Controller`.
- [ ] Преобразуй значение range к числу до передачи в RHF.
- [ ] Сделай кастомный switch «Подтверждаю условия» через `Controller`.
- [ ] Запрети отправку, пока пользователь не подтвердит условия.
- [ ] На submit отобрази типизированный JSON результата.

### Контракт `field`, который надо правильно использовать

- `field.value` — текущее значение;
- `field.onChange(nextValue)` — обновление значения;
- `field.onBlur()` — отметка поля как touched;
- `field.name` — имя поля;
- `field.ref` — нужен, когда кастомный компонент поддерживает ref.

### Проверь себя

- [ ] В коде нет отдельного `useState` для `priority`, `estimate` и `terms`.
- [ ] Нажатая кнопка приоритета отражает `field.value`.
- [ ] Range сохраняет `number`.
- [ ] У switch есть `role="switch"` и корректный `aria-checked`.

<details>
<summary>Подсказка: когда нужен Controller</summary>

Используй `register` для нативных полей. `Controller` нужен, когда компонент управляется через `value`/`onChange`, имеет нестандартное событие или не отдаёт обычный DOM ref.

</details>

**Сверка после выполнения:** `ControllerDemo`.

## Шаг 5. Динамические поля с `useFieldArray`

**Цель:** собрать список участников команды без ручного массива в `useState`.

### Данные формы

```ts
type Member = {
  name: string;
  email: string;
};

type TeamValues = {
  members: Member[];
};
```

### Сделай

- [ ] Укажи один пустой участник в `defaultValues`.
- [ ] Подключи `useFieldArray({ control, name: 'members' })`.
- [ ] Отрисуй `fields.map(...)`.
- [ ] В каждом элементе добавь `name` и `email` с валидацией.
- [ ] Добавь `append({ name: '', email: '' })`.
- [ ] Добавь `remove(index)`.
- [ ] Не позволяй удалить последнего участника.
- [ ] Отправь и покажи JSON со списком участников.

### Важное правило

Для ключа React используй **`field.id`**, а не `index`:

```tsx
// Верно: key={field.id}
// Неверно: key={index}
```

### Проверь себя

- [ ] При добавлении нового участника поля не теряют введённые данные.
- [ ] При удалении середины списка значения остальных участников остаются на своих местах.
- [ ] Ошибка одного участника отображается рядом с нужным полем.

<details>
<summary>Подсказка для имён полей</summary>

У поля участника номер `index` входит в путь: `members.${index}.name` и `members.${index}.email`.

</details>

**Сверка после выполнения:** `FieldArrayDemo`.

## Шаг 6. Большая форма: `FormProvider` и `useFormContext`

**Цель:** разбить форму на компоненты, не передавая `register`, `control` и `errors` через props на каждом уровне.

### Данные формы

```ts
type WorkspaceValues = {
  account: {
    name: string;
    email: string;
  };
  plan: 'starter' | 'team' | 'scale';
  updates: boolean;
};
```

### Компоненты

Создай:

```text
WorkspaceForm
├── AccountFields
└── PlanFields
```

### Сделай

- [ ] В `WorkspaceForm` создай методы через `useForm<WorkspaceValues>()`.
- [ ] Оберни форму в `<FormProvider {...methods}>`.
- [ ] В `AccountFields` используй `useFormContext<WorkspaceValues>()`.
- [ ] В `PlanFields` используй `useFormContext<WorkspaceValues>()`.
- [ ] Зарегистрируй вложенные поля `account.name` и `account.email`.
- [ ] Сделай выбор тарифа кнопками через `Controller` внутри `PlanFields`.
- [ ] Добавь checkbox `updates` через `register`.

### Проверь себя

- [ ] У дочерних компонентов нет props с `register`, `control`, `errors`.
- [ ] Удаление `FormProvider` ломает дочерние компоненты — это ожидаемое подтверждение, что контекст действительно используется.
- [ ] В submit приходит объект с вложенным `account`.

<details>
<summary>Подсказка</summary>

Методы из `useForm` нужно передать целиком: `<FormProvider {...methods}>`. Внутри провайдера можно вызвать `useFormContext<WorkspaceValues>()`.

</details>

**Сверка после выполнения:** `AccountFields`, `PlanFields` и `ProviderDemo`.

## Шаг 7. Асинхронная отправка и серверная ошибка

**Цель:** корректно обработать загрузку, успешную отправку и ошибку API.

### Сделай

- [ ] Сделай `onSubmit` асинхронным.
- [ ] На время запроса имитируй задержку через `Promise` и `setTimeout`.
- [ ] Получи `isSubmitting` из `formState`.
- [ ] Пока идёт submit, заблокируй кнопку и покажи «Сохраняем…».
- [ ] Для одного сценария имитируй серверную ошибку.
- [ ] Запиши серверную ошибку в `setError('root.server', { ... })`.
- [ ] Покажи `errors.root?.server?.message` над кнопкой.
- [ ] При успехе очисти форму и покажи краткое сообщение.

### Проверь себя

- [ ] Нельзя нажать submit несколько раз, пока запрос не завершился.
- [ ] Ошибка API не привязана искусственно к отдельному input.
- [ ] После успешной отправки форма возвращается в ожидаемое состояние.

<details>
<summary>Подсказка</summary>

`isSubmitting` автоматически меняется, пока Promise из обработчика `handleSubmit` не завершится. Для общей ошибки удобно использовать путь `root.server`.

</details>

**Сверка после выполнения:** `ProviderDemo`.

# Финальный челлендж — регистрация команды

Собери форму **без просмотра готового кода**. Можно использовать готовые UI-компоненты и стили проекта.

## Обязательные требования

- [ ] Тип `TeamRegistrationValues` с полями:
  - `workspaceName: string`;
  - `owner: { name: string; email: string }`;
  - `plan: 'starter' | 'team' | 'scale'`;
  - `members: Array<{ name: string; email: string }>`;
  - `acceptTerms: boolean`;
  - `coupon?: string`.
- [ ] `workspaceName`, имя владельца и email владельца обязательны.
- [ ] Email проверяется встроенным `pattern`.
- [ ] `plan` выбирается через `Controller` и кастомные кнопки.
- [ ] Список `members` работает через `useFieldArray`.
- [ ] Кнопка добавления участника disabled, когда их уже 10.
- [ ] Удаление владельца/единственного участника должно быть невозможно либо корректно обработано.
- [ ] Если выбран `scale`, покажи поле `coupon`.
- [ ] За показом `coupon` следи через `useWatch`.
- [ ] Вложенные блоки аккаунта и тарифа используют `FormProvider` / `useFormContext`.
- [ ] Submit имитирует API, использует `isSubmitting` и показывает `root.server` при ошибке.
- [ ] Результат удачной отправки отображается в JSON-панели.

## Бонусные требования

- [ ] Кнопка submit disabled, пока форма невалидна или не изменена.
- [ ] Первое невалидное поле получает фокус после submit.
- [ ] Есть кнопка «Загрузить демо-данные» через `reset(demoValues)`.
- [ ] Есть счётчик участников через `useWatch({ name: 'members' })`.
- [ ] Ошибки доступны для скринридера через `aria-describedby` и `role="alert"`.

## Мини-шпаргалка API

| Задача | API |
|---|---|
| Создать форму | `useForm<T>()` |
| Подключить native input | `register()` |
| Обработать submit | `handleSubmit()` |
| Читать ошибки и флаги | `formState` |
| Подписаться на значения | `useWatch()` |
| Изменить значение кодом | `setValue()` |
| Запустить валидацию | `trigger()` |
| Сбросить форму | `reset()` |
| Подключить controlled UI | `Controller` |
| Работать с массивом полей | `useFieldArray()` |
| Передать форму в дерево | `FormProvider` + `useFormContext()` |
| Поставить ошибку API | `setError('root.server', ...)` |
